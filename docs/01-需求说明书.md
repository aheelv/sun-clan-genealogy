# 孙氏族谱 · 静态族谱站点 — 需求说明书

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 孙氏族谱 · 静态族谱站点（sun-clan-genealogy） |
| 文档版本 | v1.0 |
| 编制日期 | 2026-09-24 |
| 数据来源 | `孙氏族谱.xlsx`（31 页世系图表）、`孙氏族谱1.doc`（前言与附录） |

## 1. 项目背景与目标

### 1.1 背景

《孙氏族谱》现存两种载体：

- **世系图表（xlsx）**：31 页二维网格，每页以列为世代、以行为房支排列，共 2,779 个非空单元格、64 处合并单元格；谱中同时记录了大量旁注（过继、少亡、孤、同名异人、参见他页、生僻字注音等）。
- **文献部分（doc）**：前言、版本沿革、凡字注记、编后话及历次校订说明，共 120 段、4,617 字。

两种载体互补：文献给出**世系骨架与命名规则**（一世祖文友公、六大支系、二十辈凡字），图表给出**逐格的人名与代际坐标**。但二者均为"人读友好、机读不友好"的形态，无法检索、无法交叉校验、无法协作修订。

### 1.2 目标

1. 把两种异构载体**归一为通用族谱数据模型**，结构化呈现；
2. 提供完整的**增删改查**能力，支持族人协作续修；
3. 建立**准确性、一致性、可校验**三重保障，把"推导"与"明载"严格区分并显式标注；
4. 以**中秋为主题**完成视觉设计，兼顾庄重与节令氛围；
5. 架构**可扩展**（新增世代、支系、字段、校验规则不改核心），并留存规范文档与原始资料。

### 1.3 非目标（本期不做）

- 不做服务端账号体系与真实鉴权（见 §5 权限设计说明）；
- 不做多人实时协同编辑（当前为单浏览器本地状态 + 文件导入导出）；
- 不做世系图表的图形化拖拽绘制（以树视图替代）；
- 不推测原谱未载的生卒年、字号、葬地等信息。

## 2. 术语表

| 术语 | 含义 |
| --- | --- |
| **世（代）** | 世代序号。一世祖文友公为第 1 世，原谱图表列标题为「三代」至「十八代」 |
| **支系** | 三世祖六兄弟（仁、礼、义、智、斌、吉）分衍的六大房支 |
| **主干行 / spine** | 原谱中横向连续填写的一行，构成一条**显式世系链**，证据强度高于规则推导 |
| **凡字** | 辈分字。第 6–15 世为「士昌道德盛裕世广大年」，第 16–25 世为「学成保国志良善福寿全」 |
| **夫妻相并** | 原谱体例：配偶以「X氏」或全名紧接在夫主之后同一列记录 |
| **旁注** | 附于人名旁的说明文字，如「过继」「少亡」「见 13 页」 |
| **出处（ref）** | 人物在原谱中的坐标 `[页, 行, 列, 原文]`，可回溯到具体单元格 |
| **证据强度** | `manual(4) > doc(3) ≈ note/adjacency(3) > spine(2) > heuristic(1)`，用于冲突消解 |

## 3. 功能需求

### FR-1 数据导入与结构化

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-1.1 | 逐格转录 xlsx 世系图表 | 2,779 个非空单元格全部落盘，含 64 处合并区间；与独立工具读取结果逐格一致 |
| FR-1.2 | 无损提取 doc 文本 | 120 段、4,617 字；保留段落边界与特殊控制符（图、表分隔符）语义 |
| FR-1.3 | 建立通用族谱数据模型 | 人物字段含 id/谱名/性别/世代/支系/状态/父/配偶/旁注/出处，字段定义集中在 `schema.js` |
| FR-1.4 | 由空间布局推导谱系语义 | 页内列标题 → 世代；同列相邻 → 配偶；连续行 → 主干链；相邻世代列最近行（+ 单一父块修正） → 父子 |
| FR-1.5 | 文献明载优先 | 《前言》所述世系链（文友→元亨/元贞→仁等）作为最高证据写入，覆盖规则推导 |
| FR-1.6 | 原文可溯源 | 每条人物记录保留原谱出处数组；跨页重复出现者保留多出处 |
| FR-1.7 | 文献部分结构化 | 前言、目录、版本沿革、凡字表、编后话、历次校订说明分节保存并原样呈现 |
| FR-1.8 | **同名异人独立** | 凡字命名下同辈共用一字，「同名 + 同世代」**不等于**同一人。实体归并须以**递归身份键 `pkey = (世代, 姓名, pkey(父))`** 判定，绝不以「姓名 + 世代」为归并键。不同父系下的同名者各自独立成记录，配偶与子女须正确归属各自分支。验收：全谱同名异人 128 组 / 295 人全部独立；独立排查工具（`diagnose_merge.py`）零疑似误合并 |

### FR-2 结构化呈现

> **呈现总原则（FR-2.0）：谱系呈现以图形为主。** 层级与血缘关系须以图形结构（树形/图形）清晰直观地表达，文字列表作为补充而非主体。站点默认落点为**「概览」**——先给出谱名、统计、校验摘要与**图形化的世系主脉**；紧随其后的**「谱系图」**视图承载完整的 SVG 全谱树，一键可达（快捷键 `g`）。谱系图默认状态即为**纵向铺展、含配偶、可读字号**——不需要用户先做任何设置。

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-2.0 | **图形化呈现为主** | 「谱系图」视图为 SVG 谱系图；以「主干人物 + 配偶」为绘制单元，树形展开层级与血缘；支持逐节折叠、缩放平移、世代背景带。**导航次序为 概览 → 谱系图 → …** |
| FR-2.0.0 | **默认落点** | 打开站点默认进入**「概览」**页（`hash = #home`），导航与底部标签栏高亮「概览」；「谱系图」列于「概览」之后。仅在 URL 显式指定视图键时才直接进入该视图 |
| FR-2.0.1 | **谱系图默认参数** | 切至谱系图即是一棵**纵向铺展**（世代自上而下）的世系树，**默认显示配偶节点**（不隐藏）；默认展开始祖以下 2 代，使首屏无需任何操作即可清晰阅读 |
| FR-2.0.2 | **加载自动适应** | 页面加载时按画布尺寸自动缩放至合适大小并居中；容器尺寸变化（窗口缩放、侧栏展开）自动重新适应，直至用户手动平移或缩放为止 |
| FR-2.0.3 | **可读字号下限** | 自动缩放设下限（`scale ≥ 0.5`，字号 ≥6.5px）。范围过大时宁可让图形溢出画布、由用户拖拽平移，也不缩到不可读；溢出时状态栏明确提示 |
| FR-2.1 | 谱系图双模式 | **世系树**（从任一祖先展开的全谱树，可切纵横朝向）与**血缘关系图**（以某人为中心的沙漏图：父辈／同辈／子辈，边上标注亲属称谓） |
| FR-2.2 | 图形语义可读 | 以颜色与线型编码证据强度：文献明载／主干行明载／推导待核／婚姻／过继，各有区分；配图例说明；过继另绘弧线，与父系实线不混同 |
| FR-2.3 | 图形交互 | 点击节点查看档案；点击 +/− 折叠展开（显示隐藏后代数）；滚轮缩放、拖拽平移、双击改根；触屏单指平移、双指捏合 |
| FR-2.3.1 | **触屏平移（放大后仍可自由拖动）** | 图形未纵向溢出时，纵向手势交还页面滚动（画布 `touch-action: pan-y`）；一旦缩放至纵向溢出，画布改为 `touch-action: none` 接管全部手势，单指横纵自由平移、斜向亦可。手势归属随每次缩放／布局变化重新判定 |
| FR-2.4 | 概览首页（**默认落点**） | 展示谱名、统计概览、独立交叉校验摘要、六大支系、世系主脉、二十辈凡字表、文献摘录、来源指纹；打开站点即见此页 |
| FR-2.4.1 | **原籍介绍可展开** | 英雄区给出原籍（山东登州府文登县孙家洼 · 小地名南桥子白果树屯）摘要；点击「展开原籍全文」补出《前言》中「从哪来、怎么落脚」的完整三段原文（原籍与流落三道嘴子／结亲迁居孙家沟子／二世分居与诸公北迁），并可一键跳转文献页 |
| FR-2.4.2 | **使用说明** | 「从这里开始」入口之后提供「使用说明」按钮，弹窗按模块（概览／谱系图／名录／文献／校验中心／权限与数据）逐条说明用法，并附快捷键与角色提示 |
| FR-2.4.3 | **入口按角色收敛** | 访客只保留必要模块（谱系图、名录检索、谱牒文献、二十辈凡字）；「校验中心」「权限与数据」等治理类模块收进「其他权限」折叠组，默认收起。非访客角色平铺全部入口 |
| FR-2.5 | 名录浏览 | 支持**世系树视图**与**列表视图**双模式；**默认「世系树」并展开全部世代**（先给全景，再按需折叠），提供「全部展开／展开至三世／全部折叠」；列表分页。检索一有输入即自动切到列表 |
| FR-2.6 | 检索 | 按谱名、注音、旁注文本、原谱单元格内容全文检索（180ms 防抖） |
| FR-2.7 | 筛选 | 按世代、支系、状态、性别、仅推导关系、仅特定旁注筛选，多条件叠加 |
| FR-2.8 | 排序 | 按世代、姓名、子女数、配偶数排序 |
| FR-2.9 | 人物档案 | 展示基本信息、旁注、原谱出处（页码与单元格引用）、世系路径、父母配偶子女、**出继／入继**、亲属称谓 |
| FR-2.10 | 文献页 | 目录 + 全文呈现，保留署名与日期 |
| FR-2.11 | 跨视图跳转 | 从概览主脉、校验报告、检索结果点击人名可直接定位到谱系图并高亮该人 |
| FR-2.12 | 易用性 | 界面清晰直观：关键操作有文字标签与提示，键盘可达（`/` 检索、`g` 回图谱、节点可 Tab 聚焦），窄屏自适应 |
| FR-2.13 | **页面跳转条** | 六个视图底部各固定一条「快速跳转」条：列出除当前页外的全部视图（图标 + 名称 + 一句用途）并附「回到顶部」。名称与图标取自同一份导航元数据，与顶栏 / 底部标签栏严格一致；支持带参跳转（如校验页「名录」项落地即筛出推导待核者） |

### FR-4 准确性与一致性

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-4.0 | **转录准确性反复校验** | 校验器与建模器**不共享代码**；只读原谱逐格转录独立重算分页、列→世代映射、主干链与候选父，再与建模产出逐项比对（C01–C12，12 项全部通过） |
| FR-4.1 | 字段级校验 | 必填、格式（谱名 1–6 汉字，生僻字可附拼音）、取值范围（世代 1–18） |
| FR-4.2 | 记录级校验 | 父不可为自身、配偶不可为自身、生卒年先后、状态与子嗣矛盾、凡字与世代一致性、配偶字段互斥 |
| FR-4.3 | 全谱级校验 | 父记录缺失、世代跳跃、世系环、世系断点、支系不一致、重复配偶、同世代同名、推导关系待核、配偶未关联、支系未定、旁注未归类 |
| FR-4.4 | 问题分级 | `error` 阻断 / `warn` 提示 / `info` 待复核，三级分明 |
| FR-4.5 | 校验中心 | **独立交叉校验结果（转录期）** + 运行时校验汇总、按级别与规则分组、可跳转到具体人物、规则目录与处置建议 |
| FR-4.6 | 一致性硬指标 | 世代跳跃 0 项、世系环 0 项、父记录缺失 0 项；凡字符合率 ≥ 90% |
| FR-4.7 | 谱系关系零明显错误 | 单元格全覆盖恒等式成立（非空格 = 标题 + 表头 + 人物引用 + 旁注）；出处逐条可回溯至原谱单元格；原谱留白如实标注而不猜测 |
| FR-4.8 | 图形不变量 | 谱系图同层不重叠、父节点居中于子节点之上、边界包住全部节点、布局确定（同输入同输出） |
| FR-4.9 | 疑点不隐藏 | 无法判定者标为「推导待核」并在校验中心集中呈现，不臆造结论 |

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首屏可交互 < 1s（本地）；1,752 人全谱检索 < 50ms；渲染 60 条/页避免长列表卡顿 |
| 兼容 | 支持原生 ES Modules 的现代浏览器（Chrome / Edge / Firefox / Safari 近年版本） |

| 可移植 | 无外部 CDN 依赖，离线可用；数据可导出为通用 JSON |
| 数据安全 | 不静默丢弃用户数据；导入前校验版本与格式；删除采用解绑策略 |

## 5. 权限设计说明

### 5.1 角色定义

| 角色 | 定位 | 典型使用者 |

### 5.3 设计要点

- **结构性字段单列权限**：世代与支系决定全谱骨架，一旦误改会引发大面积「世代跳跃」错误，故需 `person:structure`，编修角色不得触碰。
- **删除权上收**：删除有连带影响（子女解绑、配偶解绑），仅族老及以上可执行，且界面强制展示影响面。
- **重置权最高**：重置会覆盖全部本地修订，仅管理员可执行。
- **权限即文档**：矩阵由 `auth.js` 单一来源导出，管理页直接渲染，避免文档与实现脱节。

### 5.4 安全边界（必须向使用者说明）

本站为**静态站点**，数据存于浏览器 localStorage。角色机制用于**协作约束与操作留痕**，不具备密码学安全性——任何使用者都能通过浏览器开发者工具绕过。若需真实鉴权，应将同一份权限矩阵迁移到服务端 API 层复用（矩阵定义可原样搬移）。

**关于角色切换口令（FR-6.6）**：口令以常量形式写在 `core/auth.js`，会随代码一并下发给浏览器，因此

- 查看网页源代码即可读到口令；
- 在控制台直接执行 `auth.setRole('admin')` 亦可绕过闸门（`setRole` 是不过闸的低层原语）。

它的作用仅限于**阻止随手点击造成的误操作、以及挡住无意的好奇浏览**，不能替代访问控制。设计上刻意把闸门放在 UI 入口（`ui/roleGate.js` 的 `requestRoleSwitch`）而非 `setRole` 内部，正是为了让这层「软门槛」的性质在代码结构上一目了然，避免被误当成安全机制。同时，启动时**不依据 localStorage 中持久化的角色自动提权**（`Auth.restoreRole`），否则只要本地存过一次 `admin`，刷新页面即可绕过口令。

## 7. 后续可扩展方向

1. **服务端化**：将权限矩阵与校验引擎搬到 API 层，数据入库，支持多端协同；
2. **谱牒格式互通**：支持 GEDCOM 导入导出，与主流家谱软件交换数据；
3. **多媒体关联**：为人物挂接照片、墓碑拓片、口述史音频（字段已预留扩展位）；
4. **世系图可视化**：基于现有树结构实现 SVG 世系图自动排版与导出；
5. **时间轴**：结合凡字与已知年代（如六世祖士仁公 1823–1895）推算世代年代区间；
6. **检索增强**：引入同音字、异体字、繁体/简体归一，提升生僻字检索命中率。
