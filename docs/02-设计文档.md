### 1.2 依赖方向

依赖严格单向：`入口 → 视图 → 领域 → 核心 → 数据`。

- 领域层是**纯函数**，不依赖 DOM、不依赖 store 实例（输入数组，输出结果），因而可在 Node 中直接测试；
- 核心层中 `schema.js` 被所有层引用，自身不依赖任何模块（零依赖叶节点）；
- 视图层只通过 store 的公开 API 读写数据，不直接改 `store.state`。

这条约束由 `tools/check_imports.mjs` 静态检查兜底（校验每条相对导入的目标与具名导出存在）。

### 1.3 关键技术决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 是否引入构建工具 | **不引入** | 站点逻辑无编译需求；零构建意味着十年后仍能直接打开，无需复活已过期的工具链。ES Modules 原生支持已足够 |
| 种子数据是否 fetch | **内联进 `seed.js`** | `fetch('./data/x.json')` 在 `file://` 下被同源策略拦截；内联后双击 `index.html` 即可用 |
| 状态管理 | **单例 Store + 订阅** | 数据量（1,752 人）与交互复杂度不需要状态库；手写 300 行可读性优于引入依赖 |
| 关系存储 | **派生，不冗余** | 只存 `fatherId`/`spouseOfId`，父子与婚姻关系在读取时派生，杜绝"关系表与人物表打架" |
| 人物身份判定 | **递归身份键 `pkey`** | 凡字命名下同辈共用一字，「同名 + 同世代」不等于同一人。以 `pkey = (世代, 姓名, pkey(父))` 判定身份；归并与分歧检测**共用同一函数**，避免两套口径互相打架 |
| 校验引擎 | **规则注册表** | 规则为纯数据 + 纯函数，新增规则不改引擎；规则同时供表单实时校验与全谱校验复用 |
| 权限模型 | **权限键矩阵** | 角色 → 权限键 → 资源动作三层，矩阵是唯一来源，界面与文档都从它渲染 |

### 2.2 运行时数据流

```
         localStorage                ┌──────────────┐
              │  命中且版本兼容       │              │
              ├────────────────────▶ │    Store     │ ──▶ subscribe(fn)
              │                      │  persons[]   │        │
  seed.js ────┘  未命中则回落种子      │  adoptions[] │        ▼
                                     │  audit[]     │   视图重渲染
                                     └──────┬───────┘
                                            │ reindex()
                              ┌─────────────┼─────────────┐
                              ▼             ▼             ▼
                          _index        _children      派生 ctx()
                        id→person    fatherId→kids[]   供校验引擎
```

**写操作唯一入口**：`createPerson` / `updatePerson` / `deletePerson` / `updateMany` / `importPayload` / `reset`。统一流程：

```
输入 → 构造 draft → validateRecord(draft, ctx) → 有 error 则拒绝
     → 变更内存 → 维护反向引用 → 写审计 → revision++ → reindex → persist → notify
```

`revision` 单调递增，界面标题栏实时显示「修订 N · M 人」，用户随时知道自己看的是不是最新数据。

## 3. 模块设计

### 3.1 核心层

#### `core/schema.js` — 数据模型唯一权威定义（零依赖）

导出内容：

- **类型系统** `T`：`string / text / int / enum / ref / refList / refs / json`
- **闭集枚举**：`GENDER`（乾/坤/待考）、`PERSON_STATUS`（正常/少亡/孤/无后）、`RELATION_TYPE`（父子/婚姻/过继）、`EVIDENCE`（含 `strength` 数值）、`CONFIDENCE`、`NOTE_TYPE`
- **`PERSON_FIELDS`**：每个字段的类型、标签、必填、取值范围、正则、提示语、以及 **`access` 权限键**
- **`FORM_FIELDS`**：表单暴露字段与顺序
- **`DERIVED`**：不入库的派生字段（全名、世代标签、是否明载）
- **凡字表** `GEN_CHARS`（20 字）与 `GEN_CHAR_MAP`
- **`cnNum()` / `GEN_LABELS`**：中文数字世代标签（一世…二十五世）
- **`SCHEMA_VERSION`**：`1.0.0`，导入时校验主版本

设计要点：`access` 键把**权限**直接写进数据模型，使「字段级访问控制」成为模型的一等公民，而不是散落在表单里的 `if` 判断。

#### `core/validate.js` — 校验引擎

三作用域规则注册表：

| 作用域 | 触发时机 | 规则数 | 规则 ID 前缀 |
| --- | --- | --- | --- |
| `field` | 表单输入即时 | 4 | `F-` |
| `record` | 保存前 / 全谱校验时逐条 | 9 | `R-` |
| `graph` | 校验中心 / 导入后 | 11 | `G-` |

关键实现细节：`validateRecord()` = **字段级规则（必填/格式） + 记录级规则（自洽性）**。这样「表单实时校验」与「保存前校验」共用同一套字段口径，不会出现"表单说合法、保存时又说非法"的漂移。

规则条目结构统一为：

```js
{ id, level, title, scope, check }
// check 返回 null 表示通过，返回字符串表示问题描述
```

`validateGraph()` 逐条执行 graph 规则并捕获异常（异常本身转为一条 error 问题），随后对每个人物执行 record 校验，最终按 `error / warn / info` 三级分组返回，同时附带规则目录。

#### `core/auth.js` — RBAC

```js
Auth#can(perm) / canAny(...perms) / setRole(role) / onChange(fn)
Auth.matrix()        // 静态：导出完整矩阵，供管理页与文档渲染
Auth.isUnlocked()    // 静态：本会话（标签页）是否已通过口令
Auth.unlockSession() / Auth.lockSession()
Auth.restoreRole(saved)   // 静态：决定启动角色；未解锁时不恢复非访客角色
ACCESS_PASSWORD / needsPassword(role) / verifyPassword(input)
```

角色 → 权限键 → `resource:action`。详细矩阵见需求说明书 §5.2。

**口令闸门的分层**：`setRole()` 是**不过闸的低层原语**（自检脚本正依赖这一点直接设定角色），
口令校验位于 UI 入口 `ui/roleGate.js` 的 `requestRoleSwitch(auth, target, onGranted)`。
顶部角色下拉与权限页角色卡**都必须**经由它切换，不得直接调 `setRole`。
把闸门放在 UI 层而非 `setRole` 内部，是为了让「这是软门槛、不是安全边界」在结构上一目了然。

会话语义：解锁标记存 `sessionStorage`（关标签页即失效），因此**刷新页面后需重新输入口令**；
`Auth.restoreRole()` 据此拒绝在未解锁时恢复 localStorage 里持久化的非访客角色——
否则本地存过一次 `admin` 即可绕过闸门。

#### `core/store.js` — 仓储

- **SSOT**：`state.persons` 是唯一事实来源；父子由 `fatherId` 派生，婚姻由 `spouseOfId` ↔ `spouseIds` 双向维护
- **双索引**：`_index`（id→person）与 `_children`（fatherId→children[]），在 `reindex()` 中同步重建
- **过继独立**：`adoptions` 单独存储，因为它不改变父系归属，只增加一重社会关系
- **删除级联策略 = 解绑**：删人时子女 `fatherId` 置空、配偶 `spouseOfId` 置空，**不连带删除**。理由：族谱数据极度珍贵，宁可留下待核断点，也不能因一次误删连锁丢失整支
- **审计日志**：环形上限 500 条，记录 `{ts, action, detail, actor, revision}`
- **导入容错**：校验 `persons` 数组存在性 → 校验主版本兼容 → 按 `replace`/`merge` 执行

#### `core/dom.js` — DOM 工具

`h()`（hyperscript 构造器）、`append()`、`clear()`、`esc()`、`debounce()`、`modal()`、`toast()`、`confirmDialog()`、`download()`。

`h()` 采用 `h(tag, props, ...children)` 形式，props 中 `class`/`style`/`html`/`on*` 有特殊处理。全部输出经 `esc()` 转义文本节点，避免原文中的特殊字符破坏结构。

### 3.2 领域层（纯函数）

#### `domain/relation.js`

| 函数 | 职责 |
| --- | --- |
| `indexById` / `indexChildren` | 建索引 |
| `ancestorsOf` / `descendantsOf` | 祖先链 / 后代集合（BFS） |
| `detectCycles` | 环检测（带跳数上限，防止脏数据死循环） |
| `commonAncestor` | 最近共同祖先及到双方的距离 |
| `kinshipLabel` | **亲属称谓**，见下 |
| `buildTree` / `treeSize` / `pathToRoot` | 树构建与路径 |

**亲属称谓语义约定**：`kinshipLabel(a, b)` 回答「**a 是 b 的什么人**」。

判定顺序：
1. `a === b` → 本人；
2. `b` 的祖先链含 `a` → a 是长辈，取 `UP` 表（父/祖父/曾祖父/高祖父/天祖父…），**按 `a` 的性别**选 `UP` 或 `UP_F`（母/祖母…）；
3. `a` 的祖先链含 `b` → a 是晚辈，取 `DOWN`/`DOWN_F`（子/孙/曾孙…）；
4. 否则求共同祖先，`r = min(da, db) − 1`：
   - `r = 0` → 同胞（兄/弟/姐/妹，按世代与编号定长幼）
   - `r ≥ 1` → 前缀取 `COUSIN[r]`（堂/再从/三从…），同代 → `堂兄弟`；a 为长辈 → `堂伯叔`/`堂姑母`；a 为晚辈 → `堂侄`/`堂侄孙`…

> 实现要点：初版把 `UP`/`DOWN` 两张表用反了（把祖先判成后代），且性别取的是对方的性别。渲染自检的「仁是国俌的父」用例暴露了这一点，已修正为按 `a` 的性别与正确的表取词。

#### `domain/person.js`

`searchPersons`（姓名/注音/旁注/原谱单元格全文检索）、`filterPersons`（多条件叠加）、`sortPersons`（世代/姓名/子女数/配偶数）、`computeStats`、以及展示格式化函数 `displayName`、`genderLabel`、`statusMeta`、`confidenceMeta`、`evidenceMeta`、`noteLabel`、`genChar`、`refLabel`、`personFlags`。

#### `domain/branch.js`

`BRANCHES`（始祖 + 六支 + 待考，共 8 项，含色调与说明）、`branchStats`（规模与代际分布）、`mainLine`（每代取子女最多者构成的直系主干）。

#### `domain/layout.js` — 谱系图形布局引擎

本模块是「谱系呈现以图形为主」这一要求的算法底座。**纯函数、零 DOM**，只输出坐标与路径，因此可以在 Node 中直接断言（见 `tools/smoke_test.mjs` 的「谱系图形布局引擎」小节）。

**绘制单元（unit）而非单人**：一个 unit = 一名主干人物 + 其配偶们。配偶横向并列于主干右侧、虚线相连；**子女挂在主干之下**，故世代线始终沿主干延续，配偶不干扰世系走向。

**为什么不用「子树宽度求和」的朴素两趟法**：朴素法把子树当矩形打包，父节点只能居中于*矩形*之上。而 unit 是左右不对称的——主干节点偏在 unit 左缘（右侧留给配偶）。于是凡娶妻多、后代少的支系，其主干节点会在自己的矩形里偏左，父节点跟着偏，视觉上「不像他儿子」。实测朴素法只有 34% 的父节点真正居中于子节点跨度。

**采用的算法：轮廓法（Reingold–Tilford 思路）**

1. **后序**：每个节点先摆好自己的子代；
2. **兄弟依次落位**时，用「左/右轮廓」（每层相对锚点的最左/最右伸出量）求出与已放置兄弟**不重叠的最小位移**；
3. **父节点锚定于首末子节点中心的中点**，再把整组子代平移到位。

于是「父节点恰好居中于其子节点之上」成为**恒等式而非近似**（实测 433/433 = 100%），同时同层永不重叠。

轮廓量取**带符号**偏移：`left[d] ≤ 0`、`right[d] ≥ 0`。这样兄弟不重叠条件可写成一行：

```
c.rel + c.left[d] ≥ accR[d] + GAP.sibling   ⟺   c.rel ≥ accR[d] + GAP.sibling − c.left[d]
```

> 实现要点：初版把 `left` 当成正值量（`left[d] > 0`），公式少了一个负号，导致轮廓约束形同虚设——同一层出现数百处配偶与主干节点重叠。自检中的「同层无重叠」不变量一次抓出。另需注意：**横向布局时同层沿 y 排布**，重叠检查必须按朝向换轴，否则会误报。

**两种朝向**：`vertical`（世代自上而下，符合谱牒习惯）与 `horizontal`（横向铺开，适合宽扁谱系）。逻辑坐标先在 `(depth, cross)` 中求解，再由 `orient` 映射为屏幕坐标，故两种朝向的**节点集合完全一致**，仅换轴。**默认取 `vertical`**：谱牒阅读习惯是「上为尊、下为卑」，且默认视野（始祖以下 2 代、23 人）在纵向铺展时恰好能以可读字号完整呈现。

**默认视野与「可读优先」原则**

谱系图缩到极小即失去意义。实测：以始祖为根展开 4 代共 157 人时，整树逻辑宽 **8,846 px**，纯按宽度适应得到 `scale≈0.109`、字号 **1.4 px**——整张图退化为一条横向细线，纵向仅占画布 5%。这既是可读性问题，也是「看起来像左右横向排列」的根因。

因此默认视野取**始祖以下 2 代（共 3 世、23 人）**，适应比例 `0.6`（字号约 7.8 px），纵向填充由 5% 提升到 31%。由此衍生三项配套设计：

1. **缩放下限 `minScale = 0.5`**：`fitTransform` 不再无底线缩小。展开到更宽范围时图形宁可**溢出画布**、由用户拖拽平移，也不缩到读不出字。放得下则居中；放不下则以 `focus`（根人物）为锚居中，保证「从始祖看起」。状态栏在溢出时给出明确提示。
2. **纵向舒展层距（`stretchLevelGap`）**：世代数少时纵向会留大片空白。纵向布局的**宽度与层距无关**，故可在不改变横向适应比例（也就不会让节点变小）的前提下把世代间距拉开，上限 `2.2 ×` 基准层距；世代多时自动回落到基准值。
3. **加载即适应 + 尺寸变化自动重算**：首屏若容器尚未完成布局（`clientWidth/Height` 为 0），先按兜底尺寸绘制一版并在下一帧按真实尺寸重算（重试上限 5 次，避免死循环）；此后由 `ResizeObserver` 监听画布，窗口缩放、侧栏展开都会自动重新适应。`fitMode` 持续为真直到用户手动平移或缩放——用户一旦接管视角即不再打扰。

> 实现坑：`levelGap` 的校验若写成 `(levelGap && levelGap > 0)`，求值结果是**布尔** `true`，被当作 `1` 使用，层距会塌缩成 1 px（全部世代挤在同一行）。必须显式回退为数值：`Number.isFinite(levelGap) && levelGap > 0 ? levelGap : 0`。自检中「舒展后纵向尺寸增大」「舒展后世代仍严格分层」两条断言可捕获此错。

**导出 API**

| 函数 | 职责 |
| --- | --- |
| `buildVisibleTree` | 按根 / 层数 / 折叠状态裁剪出可见子树 |
| `unitWidth` | 单元宽度 = 主干 + 配偶并列 |
| `layoutTree` | 全谱树布局 → `{nodes, links, bands, bounds, stats}`；`levelGap` 可覆盖层距 |
| `layoutFocus` | 以某人为中心的「沙漏图」：父辈 / 同辈 / 子辈 |
| `parentPath` / `spousePath` / `adoptPath` | 正交折线、配偶短横线、**过继弧线** |
| `pathIds` | 根到某人的主干 id 链（用于高亮） |
| `fitTransform` | 「适应容器」的视图变换；支持 `minScale`（可读下限）与 `focus`（溢出锚点） |
| `stretchLevelGap` | 纵向舒展层距：世代少时拉开间距以填满画布高度 |

**过继必须单独连线**：旁注「过继给X为子」写在**生父所在行**，故 `fatherId` 恒为生父；养父（出继对象）由 `adoption` 关系单独表达。数据上 13 条过继关系**没有一条**的 `fatherId` 等于养父——所以「父系线即过继线」的想法是错的。`layoutTree` 为此额外产出 `kind: 'adoption'` 的**弧线**（`adoptPath`，向侧方鼓出），使「生父的实线」与「养父的弧线」能在同一张图上同时读出而不混淆；`layoutFocus` 则在父辈行同时绘出生父与养父。

**世代背景带**：每代一条浅色带并标注「N世」，坐标由布局引擎随节点一并给出（`bands`），保证与节点位置严格一致，且参与 `bounds` 计算以免被裁切。

**性能**：全谱 1,546 节点（780 主干 + 766 配偶）布局约 3–11 ms。

#### `ui/viewChart.js` — 谱系图形主视图

**两种图形模式**

- **世系树（tree）**：从某位祖先展开的全谱树。**默认纵向**（世代自上而下），主干实线相连、配偶虚线并列，可逐节折叠、缩放平移。折叠节点显示隐藏后代数（`+N`），避免「看起来这支没人」。
- **血缘关系图（focus）**：以某人为中心的**沙漏图**——上为父辈、中为本人与配偶及兄弟姐妹、下为子女，**边上标注亲属称谓**，一眼看清直系血缘。出继者额外绘出养父节点与过继连线。

**默认状态**（`state` 初始值）：`orient: 'vertical'` · `includeSpouses: true` · `maxDepth: 2` · `fitMode: true`。即打开页面即见一棵纵向铺展、含配偶、始祖以下 2 代的世系树，并按画布自动缩放到可读字号。

**适应与尺寸联动**：`fitMode` 为真时每次重绘都重新计算适应变换；`ResizeObserver` 监听画布，尺寸变化即重算。用户一旦手动平移/缩放，`fitMode` 置假，不再打扰其视角；点击「适应」按钮可恢复。首屏若容器尚无尺寸，先按兜底尺寸绘制并在下一帧重算（重试上限 5 次）。

**交互**：点击节点 → 选中并在右侧栏展示档案；点击 `+`/`−` → 折叠/展开该支；滚轮 → 以指针为中心缩放；拖拽 → 平移；双击节点 → 以该人为根重新展开；工具条提供根人物、展开层数、方向、配偶显隐、模式切换与缩放按钮。

**触屏手势归属（`touch-action` 动态切换）**

画布默认 `touch-action: pan-y`，把纵向手势让给页面滚动——这是小屏下正确的默认行为（否则用户在图上想滚页面会滚不动）。但它带来一个反直觉的失效：

> 一旦浏览器把某个手势判定为「纵向滚动」，该手势后续的 `touchmove` 事件会变为**不可取消**（`cancelable === false`），此时在监听器里调用 `preventDefault()` **不再有任何效果**。

于是当用户放大到图形纵向溢出画布、想上下拖动查看时，纵向手势已被判给页面滚动，`preventDefault()` 拦不住 —— 表现就是「手机上放大谱系图后拖不动」。这不是事件没绑上，而是手势归属在 `touchstart` 时就已经定死了。

解决办法是让归属随溢出状态变化：每次变换与重绘后重新判定图形是否纵向溢出（`contentOverflow()`），溢出则把画布改为 `touch-action: none`（全部手势归图形），未溢出则回到 `pan-y`（保留页面滚动）。同时，单指手势在**判定为拖图形之后锁定**（`one.locked`），此后不再做横／纵轴判断，允许斜向自由平移——否则放大后只能横着拖，仍然别扭。

`render_test.mjs` 的「谱系图触屏平移」小节锁定这四点：未溢出时 `touch-action === 'pan-y'` 且纵向拖动**不**平移；横向拖动**能**平移（证明监听确实生效，避免断言因事件没派发到当前 `<svg>` 而假通过）；溢出后 `touch-action === 'none'` 且纵向拖动**能**平移；锁定后斜向拖动横纵同时变化。

**可读性设计**

- **世代背景带**：每代一条浅色带并标注「N世」；
- **证据分色**：文献明载（青玉实线）/ 主干行明载（月华金实线）/ 推导待核（陶土虚线）/ 配偶（朱砂短虚线）/ 过继（朱砂弧线）——避免把推导误读为定论；
- **高亮主干**：选中人物时其祖先链高亮、其余淡化（用 CSS `:has()` 实现，不支持时自动退化为不淡化）；
- **过继角标**：节点左下角「出继」、右下角「入继N」，配合 `title` 与 `aria-label` 给出养父姓名；
- **状态角标**：少亡 / 孤 / 无后。

**实现要点**

- **SVG 必须用 `createElementNS`**：`core/dom.js` 为此新增 `s(tag, props, ...children)` 助手；用 `h()` 创建 SVG 元素会得到 HTML 元素，静默不渲染。
- **箭头 marker 需显式定义**：初版 `marker-end="url(#gcArrow)"` 指向了不存在的 `defs`，箭头不显示。现已在 `defs` 中定义，并用 `fill: context-stroke`（不支持时回退陶土色）使箭头随所属连线分色。
- **监听器清理**：每次重绘都会生成新的 `<svg>`，旧的 `window` 级 `mouseup` 监听必须显式解除，否则泄漏。`bindPanZoom` 现返回并保存 `panCleanup`。
- **`midOf` 取真实曲线中点**：二次贝塞尔的 `t = 0.5` 点不等于控制点，标签须按 `0.25·P₀ + 0.5·C + 0.25·P₂` 计算，否则过继弧线的标签会飘在曲线外。

**视图缓存**：`app.js` 用 `Map` 缓存已渲染的视图节点，切换时只做 `clear + appendChild`，避免重复渲染 1,752 人列表。数据变更时 `refreshDataViews()` 精准失效图形与名录视图，并**就地刷新**（不跳转，避免打断用户浏览位置）。

**跨视图定位**：`pick(id, { view })` 默认落在「谱系图」，传 `{ view: 'explore' }` 则在名录中定位。名录侧的 `select()` 会：

- 列表模式：计算目标在当前筛选结果中的序号，**自动翻到其所在页**并滚动到该行；
- 树模式：**展开目标及其全部祖先**，确保节点可见。

**名录默认视图与全展开的性能处理**

名录默认 `mode: 'tree'` 且 `expanded` 含全部人物 id —— 即进页先给一棵展开到十四世的全树（实测约 1,474 个节点）。这带来两处必须处理的性能点：

1. **id 映射只构造一次**。`treeNode` 原先在配偶分支里逐个调用 `byId()` 重建 `Map`，全展开时退化为 O(n²)。现由 `renderTree()` 构造一次并向下传递（`treeNode(person, cm, ids, depth)`）。
2. **选中不重建整树**。`select()` 在树模式下先就地改选中态（`applyTreeSelection()` 遍历 `.tnode[data-id]` 切换 `is-selected`）；只有目标节点尚未渲染（其祖先刚被展开）时才 `renderTree()` 重建。否则每点一个人都要重建上千个 DOM 节点。

`select()` 同时始终刷新列表（分页后仅 60 行，成本可忽略），使两个视图共用同一份 `state.selectedId`，切换模式时不会出现「一边高亮、一边没有」。检索框一有输入即自动切到列表模式 —— 找具体某个人时列表比树好用。

**首页入口的角色收敛**

`renderHome` 的「从这里开始」分两层：`essential`（谱系图／名录检索／谱牒文献／二十辈凡字，任何角色都用得上）与 `restricted`（校验中心／权限与数据，属数据治理）。访客下 `restricted` 收进「其他权限」折叠组（默认收起）而非从界面抹掉 —— 升权后仍能找回入口。非访客角色直接平铺全部入口。

> 收敛的是**首页的发现面**，不是可达性：顶栏导航与底部标签栏仍保留全部六个视图，因此访客虽在首页看不到「校验中心」，仍可经导航进入（访客持有 `validate:run`）。这样处理避免把「入口收敛」做成「功能删减」。

角色切换会失效 `home` 缓存（`syncRoleUI` 的失效列表含 `home`），否则切角色后首页仍停留在旧角色的模块布局。

> 实现要点：初版没有翻页逻辑，导致从校验中心点人名时"详情换了但列表无高亮"，渲染自检捕获后补齐。

**键盘可用性**：`/` 聚焦检索、`g` 回到谱系图；图谱节点可 `Tab` 聚焦、`Enter`/`Space` 选中。

### 3.5 导航元数据 `ui/viewMeta.js` 与页面跳转条

**唯一来源**：`VIEW_META`（`key` / `label` / `icon` / `hint`）+ `VIEW_ICONS` 是导航次序、名称与图标的**唯一**定义。顶部导航、底部标签栏、首页入口卡、各页跳转条四处共用同一份——此前顶部导航与底部标签栏各写了一套图标常量，改一个视图名要改三处且极易漏改。`viewMeta.js` 是**零依赖叶节点**（不 import 任何模块），故 `app.js` 与 `ui/*` 可同时引用而不成环；`app.js` 的视图注册表也由 `VIEW_META.map()` 派生，只补各视图的 `render` 闭包（它需要 `store` / `auth`，只能在装配点构造）。

**为什么需要跳转条**：谱系图、名录、校验中心都是数千像素的滚动页，读到末尾时顶栏早已滚出视野，想换页只能先滚回顶部。故每个视图末尾固定一条 `pageJump`，列出**除当前页外**的全部视图（图标 + 名称 + 一句用途）并附「回到顶部」。

`pageJump({ current, onNavigate, extra, note })` 的 `extra` 语义是**上下文改写**而非追加：

| 参数 | 作用 |
| --- | --- |
| `current` | 当前视图键，自身不再列出 |
| `onNavigate` | `app.js` 的 `go(key, params)` |
| `extra` | `[{ key, hint?, params? }]`，按 `key` **合并覆盖**默认项 |
| `note` | 右侧补充说明 |

按追加处理会让同一视图在条上出现两次（校验页既有「名录」又有「名录·只看推导待核」）。名称与图标一律取自 `VIEW_META`，**不随上下文改**——跳转条的可用性全在「一眼认出目标页」，与顶栏同名同图才认得出来；上下文差异只体现在用途说明（`hint`）与跳转参数（`params`）上。例如校验页给「名录」项挂 `params: { inferred: true }`，落地即筛出推导待核者（由 `go()` 调用视图暴露的 `root.__setInferred()` 完成）。

## 5. 校验与自检体系

### 5.1 独立交叉校验（转录期，Python）

**校验器与建模器必须不共享代码**，这是本项目对「原始文件的内容抓取需反复校验以保证准确性」这一要求的核心回应。

`tools/verify_data.py` 只读两个文件：

- `data/source/chart-raw.json` —— 原谱逐格转录（**事实基线**）；
- `data/genealogy.json` —— 建模产出（**受检对象**）。

分页、列→世代映射、主干链、最近行候选父等推导**全部在此独立重算一遍**，再与建模产出逐项比对。若两边一致，说明管线无实现缺陷；若不一致，则暴露真实问题。

| 校验项 | 内容 |
| --- | --- |
| C01 | 单元格往返 —— 每条出处指向的单元格，其原文必须与记录中的 `raw` 完全一致 |
| C02 | 页码归属 —— 每条出处标注的页码，必须与其行号所在页一致 |
| C03 | 世代与列一致 —— 每个人物的世代，必须等于其所在页该列的世代 |
| C04 | 单元格全覆盖 —— 全部非空单元格必须被 标题/表头/人物/旁注 恰好覆盖一次 |
| C05 | 主干链闭合 —— 独立重走每条主干行，相邻两格必须对应一条父系链或过继链 |
| C06 | 文献链核对 —— 《前言》明载的 8 条父子关系必须存在且证据为 `doc` |
| C07 | 启发式父系可解释性 —— 独立重算「相邻世代列最近行男性 + 单一父块例外」，父必落在候选集内，否则须为块内唯一父 |
| C08 | 父系属性一致 —— 父须为男、非配偶、世代 +1、非自身后代 |
| C09 | 子女反向一致 —— `childrenIds` 必须等于「以我为父」的集合 |
| C10 | 配偶不变量 —— `spouseOfId` 与 `spouseIds` 必须互斥且互为反向 |
| C11 | 计数守恒 —— 人物/配偶/旁注/出处 各类计数必须自洽且与统计字段一致 |
| C12 | 凡字独立重算 —— 独立重算凡字符合率，须与报告一致 |

`check()` 支持 `known_re` / `known_reason`，把**结构性失败**与**原谱本身的留白**分开：原谱未记的地方记入 `knownGaps` 并说明理由，而不是让校验红着。`--strict` 在任一 FAIL 时以非零码退出。

结果写入 `data/verification-report.json`，并随 `emit_seed.py` 一并入站，在「校验」与「概览」页直接展示。

**这套校验实际抓出了 6 个真实缺陷**（全部已修）：

1. **配偶字段双向重复**（766 例）—— 配偶的 `spouseIds` 里存了自己的丈夫，界面把丈夫渲染了两次。根因是建模时双向都写，已改为「配偶自身列表恒为空，夫主一律由 `spouseOfId` 表达」，并新增运行时规则 `R-SPOUSE-EXCLUSIVE` 守护该不变量。
2. **C05 误报 133 处** —— 校验器把配偶格也算进主干链，改为只走主干格后剩 6 处（真实）。
3. **C07 误报 163 处** —— 我要求逐次出现都相等，但 R10 组内定父本就会统一同组父系，改为「记录的父 ∈ 独立候选集并集」。
4. **C11 误报** —— 比较基准漏了旁注格，改为按人物引用格比对并加上完整覆盖恒等式。
5. **过继语义误判** —— 首版 R10 写成「明载永不覆盖」，导致 925/1714 人被拆开、V014 大量误报。查明真因是**过继**：主干行的链接是养父、旁注记的是生父，两者都对。改为「过继旁注（3 级）可覆盖主干行（2 级）」，并把无旁注佐证的 2 级分歧记录为 `group_conflicts` 而非强行统一。
6. **过继关系重复计数**（15 → 12）—— 同一「出继→养父」关系在原件中跨行跨页重复出现，`add_rel` 未去重。已按 `(出继子, 养父)` 去重。

### 5.2 三层自检脚本

| 脚本 | 层次 | 检查内容 | 断言数 |
| --- | --- | --- | --- |
| `tools/check_imports.mjs` | 静态 | 逐模块解析 import，校验目标文件存在、具名导出存在、default 导出存在 | 76 条导入 / 24 模块 |
| `tools/smoke_test.mjs` | 逻辑 | 数据完整性、派生查询、亲属称谓、校验引擎、检索筛选、权限矩阵、CRUD 闭环、导入导出、凡字一致性、**图形布局引擎不变量**、**适应变换与默认视野** | 104 项 |
| `tools/render_test.mjs` | 渲染 | 在 jsdom 中加载 `index.html` 并导入 `app.js`，验证启动与站名、六视图渲染、**谱系图图形产出与交互（含默认纵向 / 显示配偶 / 可读缩放）**、**触屏平移手势归属**、检索交互、**名录默认世系树并全展开**、详情面板、角色联动、**角色口令闸门**、**首页原籍展开与使用说明**、**访客入口收敛**、**六视图页面跳转条（覆盖 / 不列自身 / 带参跳转）**、主题切换、独立校验展示、管理视图 | 244 项 |

布局引擎的不变量断言（`smoke_test.mjs`）：

- 同层不重叠（纵向按 x、横向按 y，检查全部 1,546 个节点）；
- 父节点均落在子节点跨度之内，且**100% 精确居中**；
- 边界矩形包住全部节点；世代带数 = 可见世代数；
- 布局**确定性**：同输入两次调用坐标完全一致；
- 纵横两朝向**节点集合一致**，仅换轴；
- 主干路径 `文友→元亨→仁→国俌→纲→士聪`；
- 过继弧线数 = 过继关系数（12）；
- 全谱布局耗时 < 120 ms。

适应变换与默认视野的断言（同脚本）：

- **可读字号下限**：极宽谱系（全谱 53,323 px）下缩放停在下限 0.5，而未设下限时为 0.0168；下限确实抬高缩放；
- 放得下时**居中**、放不下时以**锚点**（根人物）为中心；`minScale > maxScale` 时不产生矛盾；
- **舒展层距**：单世代与世代多时均回落到基准值，世代少时拉开且不超过 `2.2 ×` 上限；
- 舒展**只改纵向**：横向尺寸逐像素不变、纵向尺寸增大、节点数不变、世代仍严格分层；
- 非法层距（布尔 `true`）被忽略并回退为基准层距（防 1 px 塌缩）；
- **默认视野**：23 人 / 3 世 / 含配偶，缩放 ≥ 0.5。

渲染层的默认视图断言（`render_test.mjs`）：

- **默认落点为「概览」**：`location.hash === '#home'`，导航前两位为 `home, chart`，高亮项为「概览」；
- 默认方向为纵向，且**世代沿竖直方向堆叠**（`y` 的聚类数 = 世代带数，`x` 的聚类数 > 世代带数）；
- 默认显示配偶（配偶节点数 > 0，按钮文案为「配偶：显示」）；
- 默认缩放 ≥ 0.5；展开 4 代后缩放**仍不低于 0.5**，且状态栏给出「超出画布」平移提示。

运行：

```bash
npm test              # 全部（含 Python 独立校验 + 三套 JS 自检）
npm run verify        # 仅独立交叉校验（Python，--strict）
npm run test:logic    # 仅逻辑层
npm run test:render   # 仅渲染层（需 jsdom）
```

`render_test.mjs` 的 jsdom 为**开发期依赖**，按以下顺序解析，不污染站点目录：环境变量 `SUNCLAN_JSDOM_HOME` → `~/.workbuddy-ai/binaries/node/workspace` → 站点本地 `node_modules`。未安装时脚本自行跳过并给出安装提示，不阻断 `npm test`。

> `agent-browser` 目前不支持 Windows，故浏览器侧自动化以 jsdom 完成；这也意味着**真实浏览器的 CSS 布局与视觉效果不在自检覆盖范围内**（见 §7.5）。

## 6. 可扩展性设计

| 扩展场景 | 需要改动的文件 | 是否需要改核心 |
| --- | --- | --- |
| 新增一个世代（如第 15–18 世续录） | 仅数据（新人物记录） | 否 |
| 新增凡字（第 26 世起） | `schema.js` 的 `GEN_CHARS` | 否（校验引擎自动读取） |
| 新增支系 | `domain/branch.js` 的 `BRANCHES` + `schema.js` 的 `branchId.options` | 否 |
| 新增人物字段（如葬地、字号） | `schema.js` 的 `PERSON_FIELDS` + `FORM_FIELDS` | 否（表单按 schema 渲染） |
| 新增校验规则 | `validate.js` 对应作用域数组追加一条 | 否（注册表模式） |
| 新增权限键 / 角色 | `auth.js` 的 `PERM` / `ROLES` / `MATRIX` | 否 |
| 新增视图 | `app.js` 的 `VIEWS` 追加一项 | 否 |
| 新增主题 | `theme.css` 追加一组令牌 | 否 |

**唯一硬约束**：新增字段若参与权限控制，必须在 `PERSON_FIELDS` 中标注 `access` 键——这是模型层的显式契约，也是"权限即文档"得以成立的前提。

## 7. 已知局限

1. **前端权限非安全边界**：数据在浏览器本地，角色机制用于协作约束与留痕，不提供密码学安全性。角色切换口令（FR-6.6）同样只是前端软门槛——口令常量随代码下发、`auth.setRole()` 可在控制台直接调用绕过。它只防误操作与好奇浏览，**不能替代访问控制**（详见需求说明书 §5.4）。
2. **启发式父子推导存在不确定性**：883 条父子关系由「相邻世代列最近行（+ 单一父块修正）」推导，占全部父子关系的 93.5%。这些关系全部标注 `parentEvidence: heuristic` 并在校验中心集中列出，供人工复核，不做默认可信处理。
3. **世代上限为 18**：`gen` 字段范围 1–18，与原谱图表现存世代一致；续修至第 19 世以上需同步调整 `schema.js` 的范围约束与 `GEN_LABELS` 长度。
4. **`heuristic` 关系的分支归属可能偏移**：若某人的真实父系未被正确推导，其支系归属也会随之偏移，校验中心以「支系不一致」规则提示。
5. **无真实浏览器测试**：`agent-browser` 目前不支持 Windows，渲染自检基于 jsdom，能覆盖 DOM 结构与事件联动，但**不覆盖真实浏览器的 CSS 布局与视觉效果**。图谱的布局正确性由布局引擎的纯函数断言保证（同层不重叠、父节点居中、边界包含等），而视觉呈现仍需人工目视确认。
6. **1 处同名同世冲突未决**：V014 报出 1 组「同名同世而明载父系相异、且不能由过继解释」的情形。按「不猜」原则，系统按各自的明载父系保留为不同人物并在校验中心列出，等待人工核断，**不做自动合并或覆盖**。
7. **原谱留白如实呈现**：第 6 页 E326–H326 连续四格「万氏／宋氏／宫氏／崔氏」未记明夫主，4 位配偶因此无法挂接到任何家庭单元，图谱中不被绘制。这是原谱本身的缺口，系统以 V006/V012 error 标注而非猜测归属。
